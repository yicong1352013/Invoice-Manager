# ADR-0002: 识别流水线从并行双源改为 OCR 优先、LLM 兜底

日期: 2026-10-22
状态: 已采纳（v0.4）

## 背景

v0.3 的流水线是并行的"双源验证"：每张发票同时跑 PaddleOCR 与 LLM 视觉模型，
两边结果逐字段比对，冲突进人工复核。它是项目的核心卖点，但有两个代价：

1. **每张发票都产生一次 LLM 视觉调用费用**，即使 OCR 已经完整识别。
2. 主流国产模型中不少无视觉能力（或按视觉模型计价更高），双源架构下这些便宜模型完全无法参与。

用户在 v0.4 需求中明确要求"优先调用 PaddleOCR 识别发票"。

## 决策

流水线改为串行降级：

1. 先运行选定 OCR 引擎（本地 PaddleOCR 3.x 默认；百度智能云增值税发票识别 API 为设置页可切换的云端引擎，手选、不自动降级）。
2. **达标判定**：关键字段齐全（与自动确认同一集合，8 项）且平均置信度 ≥ 85%（百度云结构化接口无置信度，仅按字段完整度判定）。达标 → 直接落库并按既有规则定状态，**不调用 LLM，零 API 成本**。
3. 不达标 → LLM 兜底：激活供应商支持视觉则直接读图；不支持视觉（如 DeepSeek 纯文本档）则解析 OCR 原文（新增文本版提示词）——这让任意便宜的国产文本模型真正可用。
4. OCR 与 LLM 都有结果时，比对/冲突/待审核逻辑与 v0.3 完全一致；发票状态语义不变。

PaddleOCR 同步从 2.7 升级到 3.x（PP-OCRv5），通过版本自适应调用层保持对 2.x 安装的兼容（`predict()` 优先、`ocr()` 兜底），本地引擎可单独回退。

## 后果

- 优点：清晰的 OCR 好就不花钱；无视觉模型可作兜底；云端引擎满足无 GPU/高精度场景。
- 代价与取舍：**放弃"每张发票都有双源互验"**——达标发票只有一个识别来源。缓解：达标门槛与自动确认字段集对齐，且置信度阈值可配置（`OCR_ACCEPT_CONFIDENCE`）。
- README 中"双源验证"话术相应更新为"OCR 优先、LLM 兜底；兜底发生时双源比对"。
