# ADR-0001: LLM 供应商配置存储在数据库而非 .env

日期: 2026-10-22
状态: 已采纳（v0.4）

## 背景

v0.3 及之前，LLM 供应商配置存放在 `backend/.env`：六个固定供应商（openai/anthropic/google/qwen/deepseek/zhipu）各有 `*_API_KEY / *_MODEL / *_BASE_URL` 三元组，界面上通过"配置"接口回写 .env 文件实现持久化。

v0.4 需求要求支持添加任意多个自定义 OpenAI/Anthropic 兼容端点。固定字段的 .env 无法表达动态列表（序列化为 JSON 行既脆弱又难审计），且"界面改配置→写文件→重读环境变量"的链路在多实例部署下不可靠。

## 决策

供应商配置迁移到数据库表 `llm_providers`（名称、协议、base_url、api_key、模型、视觉能力、预置/自定义、启用、排序），运行时设置存于 `app_settings` 键值表（激活供应商、OCR 引擎、百度云凭据、MCP 开关与令牌）。`.env` 只保留启动引导项（数据库连接、JWT 密钥、初始管理员）。

要点：

- 协议收敛为三种：`openai_compatible` / `anthropic_compatible` / `google`。GLM、千问、DeepSeek 预置全部走 OpenAI 兼容协议（各自的 OpenAI 兼容端点），弃用 zhipuai 专用 SDK。
- 首次启动种子六个预置供应商，并对旧 `.env` 中的密钥做一次性迁移（占位符跳过），避免升级丢配置。
- API Key 在数据库中明文存储（与原 .env 明文等价，自托管定位），但任何接口只返回脱敏形式（尾 4 位）。
- 每次识别处理前从数据库解析激活供应商并构建客户端，配置变更即时生效，不再需要重置进程内缓存。

## 后果

- 优点：任意多自定义端点；配置变更为纯数据库操作；密钥可脱敏返回；与账号体系（管理员才能改配置）天然整合。
- 代价：配置不再是纯文件（备份需连数据库一起备）；`.env` 中的旧配置字段从此被忽略（由一次性迁移承接）。
- 备选方案：继续 .env + JSON 序列化自定义列表——被否决，因解析脆弱且无法很好地支持增删改与脱敏。
