# 发票工作流与 Excel 模板

工作流将上传批次、识别审核、导出文件和发送结果持久化。首版支持 Excel 自定义列模板、既有 Word/PDF 版式、SMTP 邮件（含抄送）和企业微信智能机器人。

## 配置和启动

1. 启动 API，初始化新增业务表及默认 Excel 模板。
2. 在 `backend/.env` 设置固定的 `NOTIFICATION_ENCRYPTION_KEY`。在自己的终端运行下面命令生成一次，之后由 API 与 worker 共用并妥善保留。更换密钥前必须迁移已有渠道凭据，不能直接覆盖。

   ```bash
   python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   ```

3. 设置 `PUBLIC_BASE_URL` 为收件人可访问的前端地址；通知链接仍需登录，不包含访问令牌。
4. 管理员在“通知渠道”填写 SMTP TLS 或机器人 Bot ID/Secret。连接检查不会发消息；“发送测试”会向填写的目标发送测试通知。
5. 在“导出模板”编辑默认模板或新建模板，配置列和样式，预览或下载样例，再发布。
6. 在“工作流”选择已发布模板、导出格式、已启用渠道及收件目标，保存并启用；必须有可用 AI 配置。
7. 本地运行独立任务进程（在 `backend` 目录）：

   ```bash
   ../.venv/Scripts/python.exe -m app.workflow_worker
   ```

   默认同一数据库只有一个活跃 worker，第二个进程会明确退出。API、worker 均须常驻；本地关机后需要重新启动。Docker Compose 已包含 `workflow-worker`，不会因为修改配置文件而自动部署。

## 使用与恢复

- 上传时选择工作流；先上传发票，再明确选择附件所属发票并上传附件，最后提交批次。缺失或失败文件会阻止提交，失败项可以重试，同一文件标识不会重复建票。
- 发票列表可勾选已有发票，点击“执行工作流”，选择已启用流程并确认。确认后直接创建待执行批次，无须重新上传或再次提交；审核通过后会按所选流程导出并向配置目标发送。
- 列表执行保留已有发票和关联附件，复用识别结果及当前人工修改的字段；解析失败或没有识别结果的发票重新识别，所有发票都进行本次 AI 审核。正在识别或已经关联未结束批次的发票须先处理完成，普通用户只能执行自己的发票。
- 上传窗口的附件关联始终只显示本次成功上传的发票，关闭后重新打开普通上传窗口会开始新的本次清单。
- 工作流固定执行 OCR 和本次 AI 审核。关键问题的明确修正最多自动应用一轮，再审核一次；仍有关键问题则暂停整批。普通上传继续使用原有 OCR 优先策略。
- 运行详情展示待处理项、审核结果与修正历史。打开发票修正后刷新运行详情，填写人工确认原因，再恢复。人工确认绑定当前数据指纹，不能沿用过期页面上的确认。
- 全部通过后冻结本次数据和模板配置，生成文件并保存摘要。后续票据或模板修改不会改变已经生成的文件；发送重试复用原文件。
- 默认发送摘要和导出文件。原始发票与关联附件可分别勾选，按发票目录打包为 ZIP。
- 每个邮箱独立记录实际投递；邮件 To/Cc 展示完整收件组，每次 SMTP 信封只投递当前目标。机器人摘要与各个文件分项记录。
- 已成功项不会自动重发。通道确认未接收的临时错误最多尝试三次；可能已发送但回执丢失的项标记“结果待确认”，核对目标后选择“确认已发送”或“重新发送”，并填写原因。
- 取消阻止后续操作，已发送内容无法撤回。关联工作流的发票保留以维持执行记录，删除操作会提示原因。

## AI 审核分级

- 以下 11 项差异仅提示：购买方地址电话、购买方开户行账号、销售方地址电话、销售方开户行账号、规格型号、单位、数量、单价、价税合计大写、备注、开票人。数量、单价按展示与汇总用途处理。
- 发票类型、发票代码缺失或无法确认时仅提示；已有值与原件明确冲突时仍阻断。其余 11 项（号码、日期、购销方名称及税号、核心项目名称、不含税金额、税额、税率、价税合计）不符或存疑时阻断，不额外增加必填项。
- 忽略文本两端空白、全半角差异、相同数值的小数位差异和同一天的日期格式差异。项目名称只相差开头的分类星号也视为一致；不忽略核心文字、分类内容、数字或前导零差异。
- 提示项保留原值、差异与修正建议，不自动改值、不触发额外 AI 复核，仍可在详情页手动采纳。已有金额勾稽、关键字段完整性、数值格式与范围等硬校验继续生效。
- 审核结果的 `fields` 增加 `severity: none | warning | blocking`；`overall=pass` 表示没有阻断项，可能包含提示。历史结果保持原结论，重新审核才使用新规则，不自动恢复已暂停批次。

## 企业微信智能机器人

使用专属于本系统的 API 模式智能机器人。新连接可能替换同 Bot ID 的其他客户端连接，因此不能与另一个机器人服务共用凭据。本系统使用 PostgreSQL 锁互斥自身的发送、连接测试和目标发现。

群目标填写会话 chatid，单聊填写 userid。可通过短时“发现会话目标”在用户与机器人互动时取得目标，不保存互动消息正文。凭据由后端加密，普通用户只能看到可用渠道的非敏感摘要。

协议参考：[企业微信官方智能机器人 SDK](https://github.com/WecomTeam/aibot-node-sdk)。实际租户权限、平台文件限制和收件人可见性仍需在专用测试会话验收。

## 验证

```bash
# backend：纯函数、协议 fake 和隔离 SQLite 接口/执行账本测试
../.venv/Scripts/python.exe -m pytest tests -q

# backend：显式启用本地 PostgreSQL，自动创建并删除独立随机 schema
WORKFLOW_POSTGRES_TESTS=1 ../.venv/Scripts/python.exe -m pytest tests/test_workflow_postgres.py -q

# frontend
node --test tests/upload-modal.test.cjs
npm run build
```

PostgreSQL 检查不读取或修改业务表，验证独立进程恢复、worker 锁互斥、未知回执不会自动重发和文件保持一致。SQLite 测试不能替代 PostgreSQL 锁验证；模拟渠道不能替代真实收发验收。
